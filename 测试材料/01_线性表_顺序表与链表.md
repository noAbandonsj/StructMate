# 线性表：顺序表与链表

所属章节：线性表。适用程度：入门至基础应用。
来源说明：本材料由 AI 原创生成，供本项目学习与功能测试使用，未摘录第三方教材。文中数据均为教学示例。

## 1. 学习目标与基本约定

学习后应能区分逻辑结构与存储结构，解释顺序表和单链表的访问、查找、插入与删除过程，并根据操作条件分析时间复杂度。

线性表是具有相同数据类型的 n 个元素的有限序列。除首元素外，每个元素有且只有一个直接前驱；除尾元素外，每个元素有且只有一个直接后继。n 可以等于 0，此时为空表。线性表是逻辑结构，顺序表和链表是它的两种常见存储实现。

本材料中的“第 i 个元素”使用从 1 开始的逻辑位序；数组下标从 0 开始。因此第 i 个元素对应数组 a[i-1]。表长记作 n，顺序表容量记作 capacity，两者不同。

## 2. 顺序表的存储与访问

顺序表使用一段连续存储空间存放元素。若首元素地址为 base，每个元素占用 w 个字节，则第 i 个元素的地址为 base + (i-1) × w。计算位置无需逐个扫描，所以按位序读取的时间复杂度为 O(1)。

如果 base 为 1000，每个整数占 4 字节，第 4 个元素的起始地址就是 1012。这里假定整数大小为 4 字节，这只是本例约定，不代表所有语言或平台都如此。

顺序表支持随机访问，但不意味着按值查找总是 O(1)。在无序顺序表中查找某个值，通常需要顺序扫描，最坏时间复杂度为 O(n)。有序且支持随机访问时，可以使用二分查找，时间复杂度为 O(log n)。

## 3. 顺序表插入：青禾实验组成绩表

青禾实验组最初的成绩表为 [42, 57, 68, 91]，n=4，capacity=8。现在要在第 3 个位置插入成绩 63。合法插入位序范围为 1 至 n+1，插入下标为 2。为避免覆盖原有元素，必须从后往前移动：先把 91 从下标 3 移到下标 4，再把 68 从下标 2 移到下标 3，最后写入 a[2]=63。结果为 [42, 57, 63, 68, 91]，表长变为 5，本次移动了 2 个已有元素。

若在长度为 n 的顺序表第 i 个位置插入，且容量足够，需要移动 n-i+1 个元素。在表头插入移动 n 个，在表尾追加移动 0 个。容量不足时须先扩容或报告失败；不能因为本例容量足够，就忽略一般情况下的容量检查。

```text
insert(a, n, capacity, i, x):
    若 i < 1 或 i > n+1，报告位序非法
    若 n == capacity，报告容量不足
    对 j 从 n-1 递减到 i-1：
        a[j+1] = a[j]
    a[i-1] = x
    返回 n+1
```

本段伪代码中，若循环起点小于终点，则不执行循环。忽略扩容时，任意位置插入的最坏时间复杂度为 O(n)，表尾插入为 O(1)。动态数组按倍数扩容时，连续追加的均摊时间可以是 O(1)，但某次实际发生扩容的追加仍可能是 O(n)。

## 4. 顺序表删除与边界检查

从插入后的成绩表 [42, 57, 63, 68, 91] 删除第 2 个元素：先保存被删值 57，再把后续的 63、68、91 依次向前移动，最终逻辑内容为 [42, 63, 68, 91]，n=4，移动了 3 个元素。底层数组末尾即使残留旧值，也不属于当前线性表。

删除第 i 个元素的合法范围为 1 至 n，需要移动 n-i 个元素。删除表尾元素不移动其他元素；空表不能删除。一般删除操作最坏时间复杂度为 O(n)。判断能否访问元素时，应检查表长，不能只检查数组容量。

## 5. 带头结点的单链表

单链表结点由数据域 data 和指针域 next 组成。各结点在内存中不必连续，逻辑顺序由 next 连接。头指针保存链表入口；本材料采用带头结点的实现，头结点本身不计入表长，也不存放有效业务元素。空表满足 head.next 为空。

链表 head → 12 → 25 → 39 → 空中，如果 p 已指向数据为 25 的结点，要在其后插入新结点 s（数据为 31），应先执行 s.next = p.next，再执行 p.next = s。结果为 head → 12 → 25 → 31 → 39 → 空。如果先覆盖 p.next，又没有保存原后继，就可能丢失通向结点 39 的连接。

若已知前驱 p，删除其后继 q 的步骤是：确认 p.next 非空；令 q = p.next；执行 p.next = q.next；再按语言的内存管理方式释放或回收 q。C 中应释放动态分配的被删结点，且不能在释放后继续访问 q.next。

## 6. 如何比较操作复杂度

顺序表按位序访问为 O(1)，单链表按位序访问为 O(n)。无序顺序表和普通单链表按值查找的最坏时间均为 O(n)。

单链表在已知前驱结点后插入或删除，只修改常数个指针，时间为 O(1)。如果题目只给出目标位序，必须先遍历寻找前驱，整个操作通常是 O(n)。所以“链表插入删除一定比顺序表快”并不准确，必须说明是否已经取得操作位置。

单链表需要额外的指针空间；顺序表可能预留未使用容量。频繁按下标读取通常适合顺序表；已持有结点或前驱引用、需要频繁局部插入删除时，可以考虑链表。选择依据应是操作模式，而不是单看某一个复杂度。

## 7. 自测题

1. 顺序表长度为 6、容量为 10，在第 2 个位置插入元素，需要移动几个原有元素？
2. 在青禾实验组初始成绩表 [42, 57, 68, 91] 的末尾插入 75，新的逻辑位序是多少？需要移动几个已有元素？
3. 从 [42, 57, 63, 68, 91] 删除第 2 个元素后，表长和内容分别是什么？
4. 已知单链表结点 p，在 p 后插入 s，两个指针赋值应如何排序？
5. 已知单链表的第 i 个位置，但尚未定位结点，能否直接说插入的总时间是 O(1)？
6. 长度为 0、容量为 8 的顺序表，是否可以读取第 1 个元素？

## 8. 参考答案与解析

1. 移动 5 个，因为 n-i+1 = 6-2+1 = 5。
2. 新元素位序为 5，对应下标 4；移动 0 个已有元素，插入后为 [42, 57, 68, 91, 75]。
3. 表长为 4，逻辑内容为 [42, 63, 68, 91]；原数组未清理的尾部槽位不计入表长。
4. 先执行 s.next = p.next，再执行 p.next = s，保证保留原后继连接。
5. 不能。寻找位置通常要遍历，总时间通常为 O(n)；定位后的指针修改才是 O(1)。
6. 不可以。容量表示最多可容纳多少元素，表长为 0 表示当前没有有效元素。
