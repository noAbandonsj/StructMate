## 1. 本阶段目标和范围

完成第一条真实业务流程：

**进入网页 → 注册并自动登录 → 查看首页 → 查看自己的默认个人知识库、只读课程库和课程目录 → 刷新保持登录 → 退出。**

| 本阶段实现 | 交付表现 |
| --- | --- |
| 注册、登录、退出 | 使用用户名和密码，注册成功直接进入首页 |
| 登录状态恢复 | 刷新后读取服务端会话；过期后回到登录入口 |
| 用户资料 | 显示名称可修改；昵称支持中文 |
| 默认个人知识库 | 注册时自动创建“我的资料”，不要求先配置知识库 |
| 只读课程库 | 学生可见，不能修改课程内容 |
| 固定知识点目录 | 展示课程章节，为后续资料检索和练习提供稳定编码 |
| 数据隔离 | 只能读取本人个人库及公共课程库 |

本阶段不实现文件上传、文档向量化、模型答疑、出题、错题和报告。其入口继续明确显示准备状态，不伪造资料、学习记录或“已完成”的统计。
课程目录就绪不等于课程文档已经入库；课程资料会在下一阶段实际导入并索引。

## 2. 学生操作与桌面页面

1. 未登录访问六个学习页面时进入 /login；页面明确提供“创建账号”入口。
2. 注册页只要求用户名和密码，显示名称可选；支持粘贴、密码显示/隐藏及清晰的长度提示。
3. 提交期间禁用重复提交。注册完成自动登录并进入首页，不再要求重新填写密码。
4. 首页显示真实显示名称和知识库入口；未实现的学习功能保留准备状态，避免出现可点击但没有结果的操作。
5. 我的知识库显示“我的资料”和“数据结构课程资料”两张卡片，课程库标记“只读”；点击读取库详情，下方浏览或搜索真实课程目录。上传和课程文件导入仍待后续实现。
6. 已有用户直接登录；刷新时先恢复登录状态，再显示当前用户页面，避免闪现其他用户内容或先跳登录再跳回。
7. 顶部用户菜单提供修改显示名称和退出；修改成功立即同步页面名称。
8. 退出成功清除当前用户状态、资料缓存和页面草稿；之后重新登录不会继续显示前一个账号的内容。

从受保护页面跳到登录时保存该站内目标，登录成功返回。返回目标只能来自本项目允许的路由，不能接受外部网址。
受保护接口返回 401 时按登录失效处理；登录失败在表单原位提示。403 显示操作原因，网络失败保留当前输入和重试入口，不当作密码错误或强制退出。

## 3. 账户与会话方案

### 3.1 默认账户规则

- 用户名：3–32 位英文字母、数字或下划线；去除首尾空白并统一小写后保存，唯一约束作用于规范化值。
- 显示名称：1–32 个字符，支持中文；未填写时使用用户名，之后可修改。
- 密码：8–128 个字符，允许 Unicode、空格和粘贴，不要求固定字符组合；不去除空格、不静默截断。
- 本阶段不要求邮箱、手机、验证码、第三方登录或班级身份。

按用户要求采用简单注册登录，密码长度调整为 8–128，不增加复杂字符规则或额外验证步骤。
密码散列使用 pwdlib 的标准 Argon2 支持，由现成库完成；选型依据 [FastAPI 密码散列文档](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/#password-hashing)，此处只采用其密码处理建议。

### 3.2 会话与请求保护

采用数据库会话和随机 Cookie，不引入 JWT 与刷新令牌双体系：

- 每次成功登录生成 32 字节随机会话凭据；数据库只保存登录凭据的 SHA-256 摘要。
- 默认绝对有效期 7 天，刷新页面不延长有效期；服务重启后未过期会话仍可识别。
- Cookie 设置 HttpOnly、SameSite=Lax、Path=/，不设置 Domain；正式 HTTPS 环境开启 Secure，本地 HTTP 开发环境关闭 Secure。
- 退出撤销当前会话并清除 Cookie，不删除学习记录；同一浏览器重新登录时替换旧会话。
- 登录凭据不进入 localStorage、URL、JSON 响应或日志；前端只保存必要的用户状态。

Cookie 属性与服务端会话规则参考 [OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)；7 天为项目默认值，后续通过后端配置调整。

所有写请求进行精确的 Origin 校验，只接受配置中的前端来源或当前 API 的同源地址，拒绝缺失、null 与其他来源；注册与登录只接收 JSON。
登录后的写请求另需 X-CSRF-Token，与当前会话的随机 CSRF 值比较。CSRF 值随会话保存，前端通过注册、登录、GET /auth/me 响应或 GET /auth/csrf 取得；刷新只需一次账户请求，重复读取不轮换令牌。
CSRF 值是请求保护信息，单独持有它不能登录；数据库对登录 Cookie 凭据保存摘要，对 CSRF 值保留可读取的会话值。二者都不得出现在日志或 URL。
注册和登录尚无认证会话，通过严格来源及 JSON 类型检查防止跨站提交，不额外创建匿名会话表。
相关机制参考 [OWASP CSRF 防护](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)。

本轮不加入请求限流、验证码、邮箱验证或复杂账户管理；保留标准密码哈希、服务端会话及少量来源检查。
认证失败统一提示“用户名或密码不正确”；成功响应不包含密码散列或登录凭据。

## 4. 本阶段四个数据实体

| 实体 | 拟定核心字段 | 必要约束 |
| --- | --- | --- |
| users | id、username、display_name、password_hash、created_at、updated_at | username 唯一且非空；密码只保存散列 |
| auth_sessions | id、user_id、token_hash、csrf_token、created_at、expires_at | user_id 外键；token_hash 唯一；按到期时间判断有效 |
| knowledge_bases | id、kind、owner_id、course_code、name、created_at | personal 必须有所有者；course 无个人所有者且有固定课程编码 |
| knowledge_points | id、code、name、parent_id、sort_order | code 唯一；父节点外键；课程数据只由维护脚本更新 |

本阶段新增四张业务表，其余 12 个规划实体在对应功能阶段逐步添加。用户资料直接属于 users，不新增 profiles 表。
知识库用 UNIQUE(owner_id) 限定每用户最多一个个人库；课程库 owner_id 为空，通过唯一 course_code 保证重复初始化不新增同一课程库。
CHECK 约束限定 kind 为 personal 或 course：个人库 owner_id 非空且 course_code 为空，课程库 owner_id 为空且 course_code 非空；服务层同时复核。个人库的 owner_id 由当前用户确定，客户端不能指定所有者。

注册将用户、默认个人库和新会话放在一个短事务内；任一步失败全部回滚。密码散列先在写事务外计算，成功提交后才发送登录 Cookie。
用户名冲突以数据库唯一约束为准，重复注册不会留下多余知识库；普通读接口不隐式创建库、会话或课程数据。

## 6. 需要实现的接口

统一前缀 /api/v1；六个 /auth 接口及三个知识库与知识点接口均已实现：

| 方法与路径 | 请求 | 成功行为 |
| --- | --- | --- |
| POST /auth/register | username、password、display_name 可选 | 201；创建用户、个人库、会话，设置 Cookie；返回 user、default_knowledge_base、csrf_token |
| POST /auth/login | username、password | 200；设置新的 Cookie，返回相同的账户响应结构 |
| GET /auth/me | 当前会话 Cookie | 200；返回 user、default_knowledge_base 和 csrf_token，无密码或登录令牌 |
| GET /auth/csrf | 当前有效会话 | 200；返回该会话 csrf_token；未登录返回 401 |
| PATCH /auth/me | display_name、CSRF 请求头 | 200；修改显示名称，返回公开用户信息 |
| POST /auth/logout | 当前有效会话和 CSRF 请求头 | 204；撤销当前会话并清除 Cookie；无会话时可幂等返回 204 |
| GET /knowledge-bases | 当前有效会话 | 200；仅本人个人库及只读课程库 |
| GET /knowledge-bases/{id} | 当前有效会话 | 200；库基础信息，其他用户个人库与不存在对象均返回 404 |
| GET /knowledge-points | 当前有效会话 | 200；固定知识点目录，含父级与显示顺序 |

库基础响应包含 id、kind、name、is_readonly、created_at；列表与目录按 items、page、page_size、total 分页，page_size 最大 100。网页读取完整目录；本阶段不返回伪造的资料统计。GET /auth/me 的默认库保持原有四字段结构。
公开用户信息只包含 id、username、display_name 等必要字段。账户响应使用 Cache-Control: no-store。
用户名重复返回 409，输入格式错误返回 422，Origin 或 CSRF 校验失败返回 403，登录失效返回 401；统一错误包含 code 和 message。
