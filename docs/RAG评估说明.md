# 固定问题评估与真实验收

更新：2026-10-16。已使用真实 DeepSeek 与千问完成 30 对回答及逐题代理审阅，并保留首次问题和针对性回归；见 [真实模型闭环验收记录](真实模型闭环验收记录.md)。调用完成率、来源位置匹配与内容质量分别记录。

## 运行方式

在 backend 目录安装默认开发依赖后运行：

```powershell
uv sync --locked
# 默认仅运行 20 个开发问题
uv run --locked python -X utf8 -m capstone.evaluate_rag --split development
# 调整检索阈值等配置后，固定模型与配置，再单独运行 10 个保留问题
uv run --locked python -X utf8 -m capstone.evaluate_rag --split holdout
# 明确需要完整 30 题时使用 all
uv run --locked python -X utf8 -m capstone.evaluate_rag --split all
```

问题来自 [rag-evaluation.json](../content/rag-evaluation.json)，24 个有支持依据、6 个资料不足问题；20/10 的开发与保留划分互不重叠。保留问题不用来反复调参。可用 `--wait-seconds 180` 设置资料就绪和每个 RAG 回答的等待上限，可用 `--output` 指定新 JSON 文件，不覆盖已有输出。

生成和 Embedding 必须在后端填入正确地址、模型与密钥；适配已接入应用工厂，缺少密钥时不能运行。缺少密钥时命令会明确说明“评估未执行”，不写实测结果文件。安装使用 `--no-dev` 的环境不包含评估所需的 TestClient；这是维护者评估命令，不是生产网页功能。

## 实际执行内容

命令在配置数据目录的 evaluations 下创建独立临时运行目录，应用迁移、初始化课程、导入三份公开笔记，等待真实 Embedding 和 Qdrant 写入完成。每次仅有一个评估应用及一个 Qdrant 客户端；不使用正在运行应用的数据库、用户资料或向量目录，不需要停止原有服务。

评估通过应用业务接口注册临时账户，以 course 范围创建会话和发送问题，从消息接口读取服务端保存的回答与实际检索片段。接口由进程内 ASGI 客户端调用，不启动网页或浏览器；模型调用走应用自身接入的实际服务。每题创建新会话，避免题间历史污染。参考答案要点与预期支持位置不发送给模型。

同一生成服务还回答一遍不带检索材料的普通问题，形成普通回答与纯向量 RAG 的逐题对照。两种回答共用同一生成服务和模型配置；不声称随机模型输出可完全复现。资料不足题可能由系统直接说明未检索到依据，该行为与实际模型生成的回答一并保留。

结束时先停止工作线程、关闭数据库和 Qdrant，再移除本命令拥有的临时目录。正式数据中的账号、会话、练习和报告不受影响。输出只保留本次公开问题、回答、来源片段、实际维度与配置指纹、数据集摘要及运行参数；不保存 Cookie、CSRF、临时密码、模型密钥或服务地址。默认结果位于忽略的 data/evaluations/，不加入 Git。

## 如何核对结果

JSON 中每题保存 baseline、rag、实际 citations、预期位置的匹配情况及待填写的 review。status=awaiting_review 仅表示两种回答都已完成，质量仍未核对；部分调用失败时为 partial，不能作为正确答案。测试代码注入的服务会把整个结果标为 test_only，CLI 没有模拟模式。

自动检查只比较实际检索片段的 content_code 和 heading 与预期位置是否匹配，并列出未知引用编号。它不是语义正确率、完整召回率或答案质量评分；出现正确关键词也不代表回答正确。请逐题核对：

1. ordinary 与 RAG 的事实、条件、例子和算法步骤是否正确，在 review 中分别记录。
2. 每个引用是否确实支持对应结论，而不只是提到了相关主题。公开原文件可按 content/manifest.json 和实际内容摘要核对。
3. 资料不足问题是否明确承认当前资料不足，是否混入无依据结论；有检索片段也可能不足以回答。
4. 答案是否适合课程学习，是否需要补充条件、解释或更清楚的例子。

review 的质量字段默认 null，备注为空，reviewed_cases 初始为 0。人工审阅后记录 true/false、备注与已审题数；未审阅、失败和不适用项须与已确认正确的答案区分。不要把工具正常退出或位置匹配直接写成“RAG 效果已验收”。
