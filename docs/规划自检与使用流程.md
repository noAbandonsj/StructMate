# 项目规划自检与系统使用流程 v0.3

日期：2026-10-10。对象：项目规划、页面设计、数据库设计、接口设计和原始建表草案。

本次仅审查和修订设计文档，没有运行浏览器，没有修改页面原型，没有开发业务功能。产品定位明确为桌面网页，不包含手机端适配；浏览器自动检查暂不列入实施任务。

## 1. 自检结论

原方案的功能覆盖完整，RAG 答疑、个性化练习、错题、总结、报告和推荐之间可以形成学习流程。需要改善首次使用、跨页面衔接和统计解释，并减少首版的基础设施与数据建模工作量。

FastAPI + SQLite + Qdrant 本地模式可以继续作为既定首版方案。本次认为偏重的是其上层业务设计，而不是简单依据数据库表数评价性能。

已将首版规划收敛为：六个桌面页面，一个个人知识库加预置课程资料，题库与实时 AI 两种出题方式，可解释的练习分析，轻量文档后台处理。根据用户最新要求，实时 AI 出题不再限定为可程序验证的算法模板，概念题也可实时生成并用于练习。原始 v0.1 文档保存在 `docs/design/archive/v0.1/`，用于对照；它们不再代表完整首版实现范围。

## 2. 发现的问题和处理决定

| 问题 | 判断与影响 | 首版处理 |
| --- | --- | --- |
| 上传资料被写成学习的必经步骤 | 新用户没有教材文件也应能开始学习 | 注册后自动创建个人库，默认可用预置课程资料；上传是增强路径 |
| 对话到练习缺少明确的上下文传递 | 用户需再次选择知识点、资料和难度 | “练习这个知识点”携带已识别知识点，默认 5 题、基础难度；可展开调整 |
| 将实时出题限定为程序可验证题 | 缩小 AI 出题用途，超出用户所需的简单模式切换 | 提供题库出题 / 实时 AI 出题；AI 覆盖全部课程知识点和题目内容，不以程序验算作为门槛 |
| 混淆题库核验答案与 AI 参考答案 | 用户无法理解题目来源和反馈依据 | 题库预先核验；AI 题标明来源并按保存的参考答案反馈，保留题目反馈和错误修正 |
| 重复刷错题可以影响掌握估计 | 背住原题答案可能被误判为知识点进步 | 新题首次独立作答与复习分开统计；提示作答单独标识 |
| 文档删除导致题目撤销、错题重算 | 清理知识库可能意外改变学习历史 | 删除资料停止未来检索，来源标为已删除；同用户历史学习记录保留，删除前说明影响 |
| 26 张表含多组可推迟的拆分 | 迁移、联表、同步和维护工作多于当前需求 | 首版建议 16 个数据实体；减少版本表、复习明细表和小规模多对多关系表 |
| 所有生成任务都进入通用 jobs 框架 | 首版需要先解决统一状态、重试、恢复和目标映射 | 仅文档处理持久化轻量任务；聊天等在自身业务对象记录状态 |
| 加权表现值、固定组题比例缺少验证 | 增加实现成本，还容易制造精准评估的印象 | 首版用有效样本量和首次独立作答正确率，薄弱项按规则排序，不预设固定比例 |
| 摘要版本、学习修订号与报告过期机制 | 需要维护多个版本和全局失效逻辑 | 会话保留最新总结及截止消息；报告保留时间范围、生成时间和统计快照，重生成新报告 |
| 删除非空知识库必须逐份删除资料 | 操作繁琐且首版并不需要多知识库 | 首版固定一个个人库，支持逐文档删除；多库创建、重命名、删除后置 |
| 手机布局与浏览器自动检查被加入任务 | 超出当前桌面网页需求 | 移出首版范围；历史原型与检查记录仅供对照，本次不执行 |

## 3. 实现后的系统操作逻辑

### 3.1 第一次使用

1. 学生注册成功后自动登录，系统同时建立“我的资料”个人知识库；已有账号直接登录。
2. 首页提供“开始学习”“上传资料”“基础练习”三个入口，突出开始学习。
3. 学生选择课程章节，或直接在学习对话输入自然语言问题。
4. 初始资料范围为课程资料与本人已就绪的个人资料，范围在聊天页可见、可切换。
5. 没有个人资料不阻断学习；没有作答记录显示“尚未评估”，不虚构薄弱知识点。

### 3.2 建立个人知识库

1. 在“我的知识库”上传 PDF、TXT 或 Markdown，上传前说明类型和大小限制。
2. 页面显示“处理中 → 可用于学习”；失败则显示原因和重试入口。解析、切分等技术阶段放在可展开详情。
3. 文件处理期间可以继续学习其他已就绪资料，不能把未完成文档用于检索。
4. 处理完成后提供“基于这份资料开始学习”，自动将当前文档带入会话范围。
5. 重复文件提示已存在，支持使用既有资料；首版重新处理时该文件暂不可检索，其余资料可正常使用。

### 3.3 自然语言学习

1. 学生输入问题，系统根据会话上下文与资料范围检索相关片段。
2. 回答包含概念解释、必要的例子或算法步骤，以及真实来源引用。
3. 点击引用在同页右侧查看片段、章节或页码，再进入原文，不强迫离开聊天页。
4. 默认直接讲解；“给我提示”“用例子解释”等操作改变学习方式，不必先配置一组教学参数。
5. 学生可继续追问，也可点击“练习这个知识点”或“总结本次学习”。
6. 回答失败时保留问题，支持重试；资料不足时说明缺少依据并提供补充资料或改写问题的入口。

### 3.4 练习和即时反馈

1. 从对话进入时自动携带知识点；直接进入练习中心时选择“按章节练习”或“推荐练习”。
2. 配置区直接切换“题库出题 / 实时 AI 出题”，首次默认题库，之后记住上次选择。两种方式默认 5 题、基础难度；切换保留设置，题量、难度在“调整练习”中可修改。
3. 系统优先覆盖指定知识点或证据充足的薄弱项，避免近期重复题。题库模式从已核验题库选题，不足时明确实际题量。
4. AI 模式根据知识点、可用资料和学习情况实时出题，概念、算法、复杂度及综合内容都可生成；出题要求可选填写。结构完整即可用于练习，无须等待人工审批或程序验算。失败保留设置，提供重试和切换题库入口。
5. 学生选择答案，可请求提示。提示使用由服务端记录，不能由前端自由声明。
6. 提交后在本页显示结果、解析、资料来源和“题库题 / AI 生成”标记；AI 题显示保存的参考答案。判错题自动收录，两种模式都可继续练习。
7. 不强迫每次判错跳到错题本；可完成当前练习后查看整体结果与需要复习的知识点。
8. 错题复习、练习结束后均可返回原对话，保留上下文和滚动位置；切换出题方式只作用于新练习，保留已经开始的题目和作答记录。

### 3.5 错题复习

1. 错题本默认展示待复习内容，可按知识点筛选。
2. 选一道错题或一组错题开始复习；复习仍经过“看题 → 作答 → 解析”的流程。
3. 历次作答保留，原题重做不覆盖首次错误；不同日期连续两次答对可标记“已巩固”，再次答错回到待复习。
4. “已巩固”只描述该题的复习状态；用新的同知识点题目确认是否迁移理解，不直接等同知识点掌握。
5. 题目有问题可提交反馈；经维护者确认有误后从有效统计排除，而不是删除整段学习历史。

### 3.6 对话总结、报告与推荐

1. 对话内点击总结，系统整理本次讨论的知识点、核心结论和未解决疑问，保留总结对应的消息范围。
2. 学习报告页面默认显示最近 7 天的实时统计，首次正确率、复习次数和样本数直接可见。
3. 用户需要解释时点击“生成学习报告”，后端先固定统计，再生成文字建议；无需每次看数字都调用模型。
4. 生成报告期间可以继续学习，回到报告页可查看状态；报告标明生成时间和统计范围，保存为历史快照。
5. 推荐嵌入报告、首页和对话，显示“推荐哪份资料、对应哪个知识点、为什么推荐”。
6. 点击资料打开片段或真实资源地址，不先跳到独立推荐管理页面。

## 4. 优先优化的用户体验

| 优先级 | 优化 | 可验收行为 |
| --- | --- | --- |
| 高 | 新用户直接开始学习 | 登录后两步内进入课程对话，不要求先建库或上传 |
| 高 | 学习动作连续 | 对话进入练习自动带知识点，练习结束可回到原会话 |
| 高 | 两种出题方式易切换 | 练习配置区直接切换题库 / AI，保留知识点、题量、难度；失败不自动换模式 |
| 高 | 等待期间可操作 | 文档处理中能使用其他资料，生成报告时能继续学习 |
| 高 | 结果明确但不打断 | 题目提交后同页显示解析，自动收录错题，继续按钮保留 |
| 高 | 刷新后继续学习 | 保存会话和练习状态，刷新恢复已提交结果；未提交选择作为草稿恢复 |
| 高 | 资料删除影响清楚 | 删除前说明未来不能检索，历史对话与练习仍保留 |
| 中 | 统计可理解 | 样本数与首次正确率并列，少于 5 道独立新题不作薄弱判断 |
| 中 | 设置渐进展开 | 题量、难度、资料范围等高级选项不阻碍默认流程 |
| 中 | 摘要与推荐就地出现 | 总结留在对话，推荐点击可直接阅读依据 |
| 中 | 错误可恢复 | 失败显示具体原因、保留输入、提供重试，不只显示通用失败提示 |

未提交答案草稿仅帮助恢复页面，不作为已作答记录；实际统计只依据服务端提交结果。原文新窗口预览、桌面表格宽度、键盘操作和滚动位置属于网页体验目标。

## 5. 哪些属于过度设计，哪些应保留

**适合延期：**多个人知识库、历史版本发布切换、问题版本管理平台、多对多知识点标注全链路、独立复习明细表、摘要历史版本、全局学习修订号、通用任务系统、微服务或队列基础设施、固定比例个性化组题、同时引入混合检索与重排序、手机端和浏览器自动化。

**需要保留：**用户登录与数据隔离、资料向量化和真实引用、上传失败重试、消息生成状态、题库核验、AI 题结构校验与来源标记、答案不提前下发、一次提交一次计分、不可变题目快照、历次作答记录、首次与复习分开统计、报告统计快照及可靠来源推荐。

出题模式切换只增加现有练习对象的来源字段和页面切换控件，不增加题库管理平台、强制人工审批、模板平台或第二次模型复核流程。程序验算可在出现明确需要时作为辅助能力加入。

16 个实体只是本次业务合并结果，不是限制表数的目标。若实现过程中出现明确的关系查询或历史审计需求，可以增表；不为了减少表数而将全部业务写入一个 JSON 字段。

## 6. 修订后的首版范围与实施顺序

| 阶段 | 交付目标 |
| --- | --- |
| 基础工程（已完成） | 桌面入口、健康接口、存储连接、迁移框架及开发脚本 |
| 账户与知识库基础（进行中） | 四表与课程目录已完成；继续实现注册自动登录、会话恢复及知识库接口和网页 |
| RAG 主流程 | 导入课程资料、上传个人文本资料、轻量处理任务、真实检索、多轮答疑、来源侧栏 |
| 练习与错题 | 核验题库、实时 AI 出题、模式切换、判题、自动错题、复习历史 |
| 学习辅助 | 对话总结、直接计算的统计、按需报告、已有资料推荐 |
| 质量与交付 | 接口权限、判题与统计、失败恢复、课程问答质量和部署说明 |

质量检查仍要验证业务与 RAG 是否正确；本次不开发或运行浏览器自动检查。用户体验在桌面网页设计评审和后续实际使用中验证，不把手机布局作为验收条件。

本次自检完成时项目处于设计阶段，随后已进行基础工程初始化，当前实现状态见 [仓库说明](../README.md) 和 [开发指南](开发指南.md)。业务实现依据为修订后的项目规划、页面设计、数据库设计和接口设计；原始 schema.sql 和验证脚本是 v0.1 历史草案，不应直接据其 26 张表开始搭建首版。
