# 管理员账号与课程资料维护规划

规划日期：2026-10-17。状态：首版已实施，操作和验收见 [管理员课程资料维护说明](管理员课程资料维护说明.md)。

本文保留管理员账号及网页课程维护能力的设计依据。角色、本机授权命令、课程管理接口与页面已经接入；以下章节说明首版范围，实际命令与验证结果以维护说明为准。

## 1. 目标与范围

将课程资料的上传、处理、失败重试和更新接入网页，让维护者能够独立完成日常课程资料维护。

沿用现有 Vue 3、FastAPI、SQLite、Qdrant 本地模式和单后端进程架构，复用现有登录会话、文件校验、后台文档处理和引用快照能力。

首版增加一个“课程资料管理”页面，服务当前数据结构课程库。学生端保留原有六个学习页面和只读课程资料体验，课程目录继续沿用现有八章结构。

本规划是对原首版功能边界的补充：新增课程资料维护能力；教师端、班级、用户管理、复杂权限配置和统计大屏仍延期。

## 2. 账号与权限

统一使用现有登录页，账号分为普通用户和管理员两种角色。

| 操作 | 普通用户 | 管理员 |
| --- | --- | --- |
| 使用课程资料进行学习、答疑和练习 | 可以 | 可以 |
| 管理自己的个人资料 | 可以 | 可以 |
| 上传、重新处理、重试或删除课程资料 | 不可以 | 可以 |
| 查看其他用户的私人资料、对话与学习记录 | 不可以 | 不可以 |
| 在网页中创建管理员或修改账号角色 | 不提供 | 首版不提供 |

具体规则：

1. 用户表增加 `role`，取值为 `user`、`admin`；已有账号迁移后均为 `user`，新注册账号也默认为 `user`。
2. 首个管理员由本机维护命令指定，可将已有账号提升为管理员；同时提供查询与撤销授权的命令。具体命令形式在实施时确定。
3. 不自动将首个注册用户设为管理员，不提供默认管理员密码，注册与个人资料接口不接受角色修改。
4. 复用现有密码哈希、服务端 Cookie 会话和 CSRF 校验，不另建一套管理员认证系统。
5. 管理接口每次从服务端检查当前角色，撤销后下一次管理请求即失去权限。登录状态接口返回角色，仅用于前端展示入口与路由提示。
6. 管理员身份不会扩大其他用户私人资料、对话或学习记录的访问范围。

## 3. 管理页面与操作

管理员登录后显示“课程资料管理”入口。学生学习页内的课程资料保持只读，课程写操作集中在管理页面。

| 功能 | 首版操作设计 |
| --- | --- |
| 资料列表 | 显示文件名称、关联知识点、处理状态和更新时间；支持名称搜索和状态筛选 |
| 上传资料 | 支持现有文本型 PDF、TXT、Markdown，沿用文件类型、大小及内容校验 |
| 填写资料信息 | 上传时关联课程知识点，记录作者、来源与许可说明；自编资料可以注明自编 |
| 查看资料 | 预览或下载原文件，查看解析片段、来源及处理结果 |
| 失败处理 | 展示对维护者有帮助的失败原因，按错误类型提供重试或重新上传的指引 |
| 重新处理 | 复用现有文档任务与向量处理流程；处理中避免重复排队，完成前不参与学习检索 |
| 删除资料 | 确认时明确影响所有学习者；提交后退出未来检索并后台清理原文件与向量，保留历史学习记录与引用片段 |

上传或重新处理成功后，列表显示“可用于学习”，学生端和首页就绪统计反映实际状态。任务失败时保留文件与原因，不将“请求已接收”显示成处理成功。

来源和许可信息沿用现有课程内容记录方式；管理页面不展示模型密钥等服务端配置。

## 4. 资料更新与导入命令衔接

首版通过下面的流程更新文件内容：

**上传新文件 → 等待处理完成 → 核对内容和检索结果 → 移除旧文件。**

新文件未就绪时保留旧文件，避免先删旧资料后因新版处理失败而暂时无资料可用。首版不开发在线正文编辑、历史版本发布和回滚系统。

课程删除沿用现有历史记录保留规则：不删除学生的会话、练习、错题与报告；历史引用保留当时片段，并标明原来源已删除。删除确认中应说明原文件将被清理，与历史学习记录保留的区别。

已有课程导入命令仍用于初始化和显式维护，但必须处理以下衔接：

- 管理员已移除的预置资料不能在重复运行普通导入命令时被自动添加回来。
- 对有稳定 `content_code` 的预置资料，导入时识别已移除记录，默认跳过；恢复应由维护者显式操作。
- 失败重试只针对符合条件的现有资料，不借重试恢复已移除资料。
- 重复导入、重试和网页操作应保持去重与幂等，不覆盖历史引用或学习报告。

## 5. 实现改动范围

| 层次 | 拟实施改动 |
| --- | --- |
| 数据库 | 新增用户角色字段、默认值及取值约束；为课程维护记录必要的操作者与时间，原维护记录不补造操作者 |
| 认证 | 增加管理员权限依赖、本机授权与撤销命令；登录状态返回角色，保留现有会话机制 |
| 管理接口 | 增加专用课程资料接口，覆盖列表、上传、查看、重试、重新处理和删除；服务端同时验证角色及目标确属课程库 |
| 文档服务 | 复用文件校验、去重、解析、向量入库及清理，明确区分课程维护和个人资料写入的授权入口 |
| 导入命令 | 遵守预置资料移除记录，明确普通导入、失败重试与显式恢复的边界 |
| 前端 | 增加管理员专用入口、路由和页面，复用资料展示与上传组件；显示状态、失败反馈和必要的操作确认 |
| 文档 | 更新账号权限、课程维护说明、部署步骤、实施进度和验收结果 |

不能仅放宽通用“可读知识库”或“可写文档”判断，使管理员意外获得所有个人资料的读写权限。普通用户直接请求管理接口必须被服务端拒绝。

已有用户、个人资料、课程资料、会话、题目与历史报告均保留；迁移前按现有部署说明备份。

## 6. 分阶段实施

### 阶段 A：管理员账号基础

- 完成数据库迁移，旧账号默认为普通用户。
- 实现本机查询、授权与撤销管理员权限的维护命令。
- 接入服务端权限检查和登录状态角色返回。
- 验证注册与个人资料修改不能提升权限，以及撤销授权后管理请求被拒绝。

### 阶段 B：课程资料维护闭环

- 实现课程管理接口和必要的操作者记录。
- 复用原文预览、上传、失败重试、重新处理和删除清理能力。
- 完成普通课程导入、失败重试与已移除资料的兼容处理。
- 验证处理幂等、状态变化、历史保留，以及其他用户私人资料的隔离。

### 阶段 C：管理页面与整体验收

- 接入管理入口、列表、筛选、上传表单、处理反馈和删除确认。
- 用管理员完成上传和维护，再切换普通用户完成学习检索与引用查看。
- 运行相关后端、前端状态、迁移、类型检查及构建，并进行真实浏览器回归。
- 文档根据实际交付情况更新为已实现，记录验证证据和剩余限制。

## 7. 验收标准

1. 管理员通过同一个登录页登录后可进入课程资料管理；普通用户无入口，直接访问管理接口也被拒绝。
2. 普通注册账号无法通过提交 `role` 或修改个人资料获得管理员权限；撤销管理员后，原会话的后续管理请求被拒绝。
3. 管理员上传一份资料并关联知识点，处理完成后普通用户能看到并用于答疑，引用能定位到真实原文。
4. 资料处理失败可查看原因并按条件重试；生成与向量服务未配置或不可用时不显示虚假就绪。
5. 处理中重复点击不会产生重复处理任务，同文件重复上传有明确反馈。
6. 删除课程资料后不再参与新检索，历史学习记录和引用片段保留；普通导入与失败重试不会自动恢复该资料。
7. 管理员不能访问其他用户的个人资料、对话、错题或学习报告。
8. 原有注册登录、个人资料、课程学习、练习与报告功能通过回归。

验收目标是管理员能够在网页中完成课程资料日常维护，同时保持普通用户的权限边界与历史学习数据完整。
