# 接口设计 v0.3：桌面首版

更新：2026-10-12。状态：健康接口 /api/v1/health 及六个 /auth 接口已实现，其余为待实现契约。依据精简数据模型；不依赖旧版通用 jobs 框架。前缀 /api/v1。

## 1. 通用约定

JSON 请求与响应使用 UTF-8；上传使用 multipart，聊天使用 SSE。ID 使用 UUID，时间统一保存 UTC，首版日期显示与范围计算采用 Asia/Shanghai。

列表返回 items、page、page_size、total，page_size 最大 100。创建返回 201，后台处理返回 202，错误包含可理解的 code 和 message。日期范围 from_date、to_date 两端包含，后端转换成 UTC 半开区间；无分母比例返回 null。

使用数据库会话和随机登录 Cookie，保护个人资料与学习记录；登录后的写操作校验 CSRF 和 Origin，注册与登录校验 Origin 且仅接受 JSON。登录凭据不放 URL 或响应正文，密钥不返回前端。密码散列使用成熟库，不额外建设认证平台。具体会话、Cookie 和账户规则见 [下一阶段实施规划](../下一阶段实施规划.md)。

消息发送、组题、报告等生成动作及作答采用 client_request_id。相同键和相同内容返回原结果，不同内容复用同键返回 409。提示、反馈等动作按条目幂等处理，普通读取无须请求标识。

未登录 401，无权访问私人对象 404，修改只读课程资源 403；状态冲突 409，格式或参数错误明确返回，模型不可用 503。页面将技术错误转换成可恢复的学生操作提示。

## 2. 账户与固定知识库

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | /health | 最小健康状态 |
| GET | /auth/csrf | 当前有效会话的 CSRF 值，不轮换；未登录 401 |
| POST | /auth/register | 201；注册、建立默认个人库并自动登录，设置 Cookie；返回用户、默认库和 CSRF 值 |
| POST | /auth/login | 200；设置 Cookie，返回用户、默认库和 CSRF 值，无登录凭据 |
| POST | /auth/logout | 204；撤销当前会话、清除 Cookie；无会话可幂等返回 204 |
| GET | /auth/me | 当前用户、默认个人库及 csrf_token，一次请求恢复账户 |
| PATCH | /auth/me | 显示名称；不增加首版时区设置 |
| GET | /knowledge-points | 固定课程知识点目录 |
| GET | /knowledge-bases | 本人个人库及可读课程库 |
| GET | /knowledge-bases/{id} | 下一阶段返回库基础信息；文档模块实现后再加入资料状态统计 |

首版不提供多知识库创建、重命名、销毁接口。预置课程库通过维护脚本管理；学生只能向本人个人库上传资料。

本节账户接口已实现；下一步实现知识库基础和知识点目录。资料上传与下列业务接口后续逐步接入；不得以模拟数据表示业务已完成。当前账户使用简单用户名密码登录，密码 8–128 个字符，不增加验证码、找回密码、请求限流等流程。

## 3. 文档与轻量处理任务

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | /knowledge-bases/{id}/documents | 文档列表、就绪或失败状态 |
| POST | /knowledge-bases/{id}/documents | 上传，202 document_id 和状态；重复内容返回既有资料 |
| GET | /documents/{id} | 文件信息、当前状态、处理详情和 retryable |
| GET | /documents/{id}/file | 授权读取未删除原文件 |
| GET | /documents/{id}/chunks | 当前就绪片段、正文、位置和知识点 |
| POST | /documents/{id}/process | client_request_id；首次失败重试或主动重新处理，202 |
| DELETE | /documents/{id} | 202 清理；立即禁止未来检索，保留历史学习记录 |

首版 PDF、TXT、MD，单文件默认 20 MiB，可由后端配置。内部 document_tasks 保存状态、错误与有限重试，页面轮询文档对象即可，不向学生暴露统一任务中心。

文档状态为 processing、ready、failed、deleted；内部可保存解析阶段，不要求显示假的百分比。重新处理期间当前资料暂不可检索，其余资料可用。重启后中断文档标记失败或按幂等步骤恢复，允许明确重试。

上传完成后可创建仅使用该文档的会话，或者加入默认课程与个人资料范围。删除接口不撤销已有题目或清空错题；删除影响通过确认文案告知。

## 4. 对话与真实引用

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | /conversations | 本人会话列表 |
| POST | /conversations | 标题、scope、document_ids 可选；201 |
| PATCH | /conversations/{id} | 标题、资料范围、归档 |
| GET | /conversations/{id}/messages | 按顺序读取消息、状态与引用列表 |
| POST | /conversations/{id}/messages | content、client_request_id；202 回答标识和 stream_url |
| GET | /messages/{id}/events | 同源 SSE，鉴权读取本人回答 |
| POST | /messages/{id}/cancel | 取消尚未完成回答 |
| POST | /messages/{id}/retry | client_request_id；为最近失败问题创建新回答 |

scope 可为 course、personal、combined，默认 combined；document_ids 仅限当前用户可访问且就绪资料，由后端校验。会话范围保存为结构化字段，历史回答保留当时来源。引导思考或例子解释可通过消息意图或简短 action 字段表达，不增加教学策略管理接口。

发送返回 assistant_message_id、user_message_id、stream_url，不再返回泛化 job_id。回答通过 reply_to_message_id 关联同一会话中的用户问题。并发同会话生成返回 409，界面显示当前生成状态。

SSE 采用 snapshot、delta、citations、completed、failed、cancelled。连接先以快照恢复内容，再接收增量；终态关闭连接。不建设逐事件重放、事件历史表或通用任务总线。来源列表嵌入消息对象，点击片段时仍验证权限和删除状态。

最新问题的失败或取消回答可重试，已有后续问题时提示重新提问。页面离开不直接等于取消，刷新后读取消息状态恢复。首版启动恢复仅把中断回答标记失败，避免重复模型调用。

## 5. 练习与错题

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| POST | /practice-sessions | mode、question_source（bank/ai，默认 bank）、knowledge_point_ids、count 默认 5、difficulty 默认基础、generation_requirements 可选、source_conversation_id 可选、client_request_id；202 |
| GET | /practice-sessions | 本人历史练习列表 |
| GET | /practice-sessions/{id} | 状态、question_source、练习设置、题目进度、实际数量、来源会话、已提交结果 |
| GET | /practice-sessions/{id}/items | 题干、选项、source_type、提示使用；未提交题不下发答案 |
| POST | /practice-items/{id}/hint | 记录提示使用，返回提示 |
| POST | /practice-items/{id}/attempts | answer、client_request_id；201 结果、保存的答案、解析、引用、source_type 和错题标识 |
| POST | /practice-items/{id}/feedback | 保存题目反馈理由，维护脚本可读取 |
| GET | /wrong-questions | 复习状态、知识点筛选 |
| GET | /wrong-questions/{id} | 原题与历次有效作答 |
| POST | /wrong-questions/review-sessions | wrong_question_ids、client_request_id；创建复习 |

mode 为 chapter/adaptive，question_source 为 bank/ai，分别表示选知识点的方式和题目来源，两者独立。review 从专门复习入口创建，question_source 为空，按原题快照复习；每题仍返回自己的 source_type。对话跳转只携带知识点等建议，服务端仍核验会话所有权与知识点，AI 出题沿用其可访问资料范围。组题状态保存在 practice_sessions，不使用泛化 jobs。

bank 从预核验题库选择；ai 根据知识点、可用资料、学习情况和可选 generation_requirements 实时生成题目。AI 可生成概念理解、算法过程、复杂度分析和综合应用等内容，不限算法模板或能否程序验算。服务端校验题目结构与答案格式，不设置逐题人工审批或程序验证门槛；bank 模式不接受 AI 出题要求。

无记录时推荐基础测验；推荐判断使用最近 30 天不同新题的首次独立作答，少于 5 道不称为薄弱知识点。题库数量不足明确说明实际题量。AI 生成失败保存 failed 状态和可恢复原因，前端保留配置；重试创建新请求和练习，或由用户选择 bank 后重新提交，不自动回退题库。

切换仅影响新练习，不提供修改已开始练习 question_source 的接口。两种方式采用相同的题目读取、提示、提交、错题和复习接口。服务端按分发快照中的答案判题，AI 题答案在页面标为参考答案，并通过 source_type 保持来源可辨认。

题目分发后内容不可变；同条目只提交一次，换请求标识也不能重复计分。使用提示由服务端标记，不能由客户端指定评分。无效题不计入当前统计，停用状态可见，不隐式删除学习历史。

返回原会话由 source_conversation_id 支持，练习位置与已提交结果可从会话详情恢复。未提交选项是本地草稿，不创建 attempts。

## 6. 总结、实时统计、报告与推荐

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| POST | /conversations/{id}/summary | client_request_id；202，在会话对象保存最新总结与截止消息 |
| GET | /conversations/{id}/summary | 最新总结、生成状态和截止消息 |
| GET | /conversations/{id}/summary/export | 完成后导出 Markdown |
| GET | /learning/overview | 首页最近会话、基础统计、待复习信息 |
| GET | /learning/stats | from_date、to_date；默认最近 7 天，直接返回统计，无需模型 |
| POST | /reports | 日期范围、client_request_id；202 report_id 和状态 |
| GET | /reports | 本人历史报告 |
| GET | /reports/{id} | 生成状态、统计快照、解释、范围和生成时间 |
| GET | /reports/{id}/export | Markdown 导出 |
| GET | /recommendations | 可选 knowledge_point_id，实际来源与规则解释 |

总结在会话内保存最新内容，排除失败消息；旧总结被新总结替换，不建设历史摘要列表。报告统计先固定快照再在事务外生成解释，生成失败仍可查看实时数字。

报告页指标采用用户所选范围；推荐练习的知识点分析使用最近 30 天，必须显示这个分析范围，不能混用两套日期口径。没有记录显示零题量和 null 正确率，少量记录显示证据不足。

统计包含有效题库题和 AI 题，AI 作答按保存的参考答案计分；统计口径注明包含两种来源，不将 AI 题仅因未经程序验算排除。已确认有误的题目依照同一有效性规则排除。

历史报告保留生成时口径，重新生成新报告；本版无 learning_revision、全局过期检测或自动级联重生成。报告明显标注历史快照，当前统计另取 /learning/stats。

推荐候选来自有权限的文档片段及维护的资源，模型只可选解释；无模型也能提供匹配理由，不能生成不存在的链接。

## 7. 页面操作与接口衔接

| 操作 | 调用逻辑 |
| --- | --- |
| 第一次使用 | register 自动登录并建个人库 → knowledge-bases；课程文档和对话功能就绪后直接开始学习 |
| 已有账号 | login → me 恢复当前用户 → knowledge-bases；退出或换账号清空原用户缓存 |
| 上传后学习 | POST documents → 轮询 document 状态 → POST conversation 带 document_ids |
| 对话答疑 | POST messages → GET events → 消息中的引用支持同页查看 |
| 对话进入练习 | 选择 bank/ai → POST practice-sessions 带 question_source、知识点及 source_conversation_id → GET items |
| 切换出题方式 | 保留页面配置，下一组 POST practice-sessions 使用新 question_source；旧练习仍可继续 |
| 判题与错题 | POST attempts → 原位结果 → GET wrong-questions，继续下一题 |
| 复习 | POST review-sessions → 普通练习条目与作答接口 |
| 查看与生成报告 | GET learning/stats 立即显示数字 → 需要解释才 POST reports |
| 总结与推荐 | 当前会话 summary、已有 recommendations，减少页面跳转 |

接口权限、判题和统计仍需实现阶段验证；当前不开发浏览器自动检查和手机端接口分支。
