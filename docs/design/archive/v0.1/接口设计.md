# 接口设计 v0.1

创建：2026-10-09；更新：2026-10-10。状态：开发契约草案，接口尚未实现。前缀 `/api/v1`，请求与响应使用 UTF-8 JSON；上传和 SSE 除外。

## 1. 公共约定

- ID 为 UUID 字符串；时间为 UTC ISO 8601，日期统计按用户时区处理。
- 成功响应直接返回对象；列表返回 `{ "items": [], "page": 1, "page_size": 20, "total": 0 }`，`page_size` 最大 100。
- 创建对象返回 201；后台处理返回 202 并包含 `job_id`；删除登录会话等立即操作返回 204。
- 日期范围使用 `from_date`、`to_date` 和 `timezone`，两端日期都包含；后端转换为 UTC 半开区间 `[start, next_day_after_end)`，无记录的比例为 null。
- 写入或生成请求需要 `client_request_id` 的接口在表中标注。相同用户、相同接口语义、相同键及相同载荷返回原结果；不同载荷复用同键返回 409。
- 返回错误 `{ "error": { "code": "...", "message": "...", "details": {} }, "request_id": "..." }`，不返回模型密钥、堆栈或数据库绝对路径。
- 未登录返回 401；无权访问私人对象返回 404；修改可读课程资源返回 403；状态冲突返回 409；文件过大 413；不支持的格式 415；参数错误 422；模型暂不可用 503。

## 2. 登录与权限

采用服务端会话：登录返回会话 Cookie 和 CSRF 令牌。Cookie 使用 HttpOnly、SameSite=Lax，HTTPS 部署启用 Secure；数据库仅保存令牌摘要，令牌不放 URL。

登录前通过 `GET /auth/csrf` 获取短期预会话 CSRF 令牌，所有写操作携带 `X-CSRF-Token` 并校验同源 Origin；登录后轮换令牌，刷新页面通过 `/auth/csrf` 获取当前会话令牌。开发前端使用代理维持同源调用。

| 方法 | 路径 | 主要输入与返回 |
| --- | --- | --- |
| GET | `/health` | 最小健康状态，不暴露密钥或本地路径 |
| GET | `/auth/csrf` | 预会话或当前会话 CSRF 令牌 |
| POST | `/auth/register` | username、password、display_name；201 用户资料 |
| POST | `/auth/login` | username、password；200 用户资料、CSRF 令牌及 Cookie |
| POST | `/auth/logout` | 撤销当前登录；204 |
| GET | `/auth/me` | 当前用户资料 |
| PATCH | `/auth/me` | display_name、timezone；更新后的资料 |
| GET | `/knowledge-points` | 课程知识点树；可选 parent_id |

普通用户只能管理自己的知识库、会话、练习、错题和报告。课程预置知识库和题目对学生只读；模型配置使用服务端环境变量，首版没有前端密钥管理页面。

## 3. 知识库、资料与任务

| 方法 | 路径 | 主要输入与返回 |
| --- | --- | --- |
| GET | `/knowledge-bases` | 当前用户个人库 + 可读课程库；visibility 筛选 |
| POST | `/knowledge-bases` | title；201 个人知识库 |
| GET | `/knowledge-bases/{kb_id}` | 标题、可见范围、文档统计 |
| PATCH | `/knowledge-bases/{kb_id}` | title；只能修改个人库 |
| DELETE | `/knowledge-bases/{kb_id}` | 空库 204；非空 409，先明确处理其中资料 |
| GET | `/knowledge-bases/{kb_id}/documents` | 文档分页、状态筛选 |
| POST | `/knowledge-bases/{kb_id}/documents` | multipart：file；202 document_id、version_id、job_id；重复内容返回 200 既有文档 |
| GET | `/documents/{document_id}` | 文件信息、最新处理状态、当前可检索版本、job_id |
| GET | `/documents/{document_id}/file` | 授权后返回原始文件，响应指定内容类型 |
| GET | `/documents/{document_id}/chunks` | 当前 ready 版本片段分页；来源定位、正文、知识点 |
| POST | `/documents/{document_id}/reprocess` | client_request_id；202 新版本与任务，不在完成前覆盖旧版本 |
| DELETE | `/documents/{document_id}` | 202 清理任务；立即阻止新检索；重复删除返回既有任务或完成状态 |
| GET | `/jobs/{job_id}` | status、stage、progress、error、target_id、retryable |
| POST | `/jobs/{job_id}/retry` | client_request_id；原任务 failed 且允许重试时返回 202 新任务 |

资料格式首版仅 PDF、TXT、MD；默认单文件上限 20 MiB，配置可调整。PDF 为空或需要 OCR 时任务失败并提示。任务 retry 首版允许 ingest、practice、summary、report；chat 通过聊天重试接口，删除任务由原删除入口恢复。

入库阶段为 queued/parsing/chunking/embedding/ready/failed/cancelled；统一任务状态为 queued/running/completed/failed/cancelled。job 的 stage 与业务对象状态区分，进度仅在可计算时展示。

单机重启时：未结束入库和组题等可幂等任务恢复或重新排队；中断的聊天标记失败，由学生主动重试，不能在重启后悄悄重复模型调用。

## 4. 会话与流式回答

| 方法 | 路径 | 主要输入与返回 |
| --- | --- | --- |
| GET | `/conversations` | 会话分页，支持 archived 筛选 |
| POST | `/conversations` | title、kb_ids、teaching_mode；201 会话 |
| GET | `/conversations/{conversation_id}` | 当前范围、教学模式和会话信息 |
| PATCH | `/conversations/{conversation_id}` | title、kb_ids、teaching_mode、archived；只影响后续回答 |
| GET | `/conversations/{conversation_id}/messages` | 按 sequence_no 顺序分页，状态及引用摘要 |
| POST | `/conversations/{conversation_id}/messages` | content、client_request_id；202 用户消息、回答占位和 job_id |
| GET | `/messages/{message_id}/events` | SSE，仅限本人会话中的 assistant 消息 |
| POST | `/messages/{message_id}/cancel` | 202 取消请求；completed 后返回 409 |
| POST | `/messages/{message_id}/retry` | client_request_id；202 为同一用户问题创建新回答，不覆盖失败历史 |
| GET | `/messages/{message_id}/citations` | 真实来源、定位、摘录与 available 标记 |

发送示例（示例 ID 以占位符表示，正式请求必须使用合法 UUID）：

```json
{
  "content": "循环队列为什么要预留一个位置？",
  "client_request_id": "<request_uuid>"
}
```

响应：

```json
{
  "user_message_id": "<user_message_uuid>",
  "assistant_message_id": "<assistant_message_uuid>",
  "job_id": "<job_uuid>",
  "stream_url": "/api/v1/messages/<assistant_message_uuid>/events"
}
```

前端先 POST 创建回答，再以同源 EventSource GET 读取 SSE，避免原生 EventSource 无法直接提交 POST 正文的问题。Cookie 完成鉴权，不在流式 URL 放令牌。[SSE 事件格式与 EventSource](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)。

事件顺序与语义：

```text
event: snapshot
data: {"message_id":"<id>","content":"","status":"generating"}

event: delta
data: {"text":"循环队列通常通过……"}

event: citations
data: {"items":[{"number":1,"title":"栈与队列讲义","location":{"page":8}}]}

event: completed
data: {"message_id":"<id>","status":"completed"}
```

失败发送 `failed`（code、message、retryable），取消发送 `cancelled`；连接保活使用注释行。前端收到终态后关闭 EventSource，防止反复重连。

每次连接先用 snapshot 替换当前展示正文，再接收后续增量；首版不做逐事件重放，也不承诺 Last-Event-ID 恢复。后端订阅和快照读取采用同一生成缓冲协调，避免连接瞬间丢失或重复增量。客户端断开不等于取消生成；明确取消需调用 cancel。服务重启后的部分文本保留为失败消息，摘要排除失败消息。

同会话已有 queued/generating 回答时，新发送返回 409 `CONVERSATION_BUSY`；独立会话可以并发，整体模型调用设有限并发。归档会话只读，先取消活跃回答后归档。

回答通过 `reply_to_message_id` 明确关联用户问题。首版只允许重试最近用户问题对应的失败或取消回答；已有后续问题时返回 409 `RETRY_NOT_LATEST`，避免把旧问题的补答混入新的对话上下文。

## 5. 练习、作答与错题

| 方法 | 路径 | 主要输入与返回 |
| --- | --- | --- |
| POST | `/practice-sessions` | mode、knowledge_point_ids、kb_ids、difficulty、count、client_request_id；202 session_id、job_id |
| GET | `/practice-sessions` | 历史练习分页 |
| GET | `/practice-sessions/{session_id}` | 状态、requested_count、actual_count、warnings 和进度 |
| GET | `/practice-sessions/{session_id}/items` | 实际题目版本、题干、选项、知识点；未提交题不含答案或解析 |
| POST | `/practice-items/{item_id}/hint` | 标记使用提示并返回提示；重复调用不重复计数 |
| POST | `/practice-items/{item_id}/attempts` | answer、client_request_id；201 判题、解析、来源与错题状态 |
| POST | `/practice-items/{item_id}/feedback` | reason；201 题目问题反馈，重复反馈返回既有条目 |
| GET | `/wrong-questions` | status、knowledge_point_id、due_only；错题分页 |
| GET | `/wrong-questions/{wrong_id}` | 原题、有效作答历史、复习历史和解析；撤销题隐藏正文并标注状态 |
| POST | `/wrong-questions/review-sessions` | wrong_question_ids、client_request_id；202 复习会话和任务 |

普通练习 mode 为 chapter/adaptive，count 为 1–20。复习使用专门入口并由服务器设置 mode=review。初次没有学习记录时，自适应练习按所选章节提供基础测验，不声称已经识别薄弱项。

题库候选只选本人私有题和课程题；私人资料生成的题不可用于其他用户。正式练习仅使用 verified 题目版本。生成不足时使用核验题库，仍不足则减少实际题量并返回 warnings；不能用未经核验的题补足数量。无可用题时返回 failed 状态和明确原因。

单选答案示例 `{ "option_id": "B" }`，判断答案示例 `{ "value": true }`；判题由服务端读取核验答案。未提交题目返回字段白名单，不能先发送答案再靠页面隐藏。

作答响应示例：

```json
{
  "attempt_id": "<attempt_uuid>",
  "outcome": "incorrect",
  "correct_answer": {"option_id":"B"},
  "explanation": "预留一个位置可以区分队空与队满。",
  "wrong_question_id": "<wrong_uuid>",
  "review_status": "pending"
}
```

同条目不可通过换 request_id 重复提交；重做创建新条目，历史答案保持不变。题目已撤销时提交返回 409 `QUESTION_REVOKED`；客户端不能自行宣布已巩固。复习成功后的状态根据有效作答及不同日期的规则更新。

## 6. 总结、报告、首页与推荐

| 方法 | 路径 | 主要输入与返回 |
| --- | --- | --- |
| GET | `/conversations/{conversation_id}/summaries` | 会话总结列表 |
| POST | `/conversations/{conversation_id}/summaries` | through_message_id、client_request_id；202 summary_id、job_id |
| GET | `/summaries/{summary_id}` | 状态、Markdown、原会话与消息范围 |
| GET | `/summaries/{summary_id}/export` | 完成后返回 Markdown 文件；未完成 409 |
| GET | `/learning/overview` | 首页：最近会话、有效题量、待复习数、证据充足的薄弱项 |
| GET | `/learning/knowledge-points` | from_date、to_date、timezone；表现估计、样本量、证据状态 |
| POST | `/reports` | from_date、to_date、timezone、client_request_id；202 report_id、job_id |
| GET | `/reports` | 报告历史分页 |
| GET | `/reports/{report_id}` | 状态、统计快照、Markdown、is_outdated、数据截止时间 |
| GET | `/reports/{report_id}/export` | 完成后返回 Markdown 文件 |
| GET | `/recommendations` | knowledge_point_id 可选；来源类型、定位或真实 URL、理由、难度 |

总结截止消息必须属于当前会话，内容取该序号及之前 completed 的消息；至少存在一条 completed assistant 回答才能生成。无练习的报告返回零题量、null 正确率及起步建议，不伪造表现。

报告统计在读取一致的 SQLite 快照时计算，并固定 `data_cutoff_at` 与 `learning_revision`，随后在事务外让模型生成解释；禁止模型改写统计数字。旧报告保留原快照，显示过期标记后由用户重新生成。

推荐采用数据库候选的确定性排序，再可选生成简短解释。模型不可用时仍返回规则生成的推荐原因。个人片段推荐每次验证资料权限、删除状态和活跃版本；外链来自维护的资源库。

## 7. 页面与调用顺序

| 用户操作 | 调用顺序 |
| --- | --- |
| 上传资料 | POST documents → GET jobs → GET document/chunks |
| 学习提问 | POST messages → GET events → completed 后查看 citations |
| 开始练习 | POST practice-sessions → GET jobs/session → GET items |
| 提交答案 | POST attempts → 更新题目结果和 overview/wrong-questions |
| 复习错题 | POST review-sessions → GET items → POST attempts |
| 总结对话 | POST summaries → GET jobs → GET summary/export |
| 生成报告 | POST reports → GET jobs → GET report/export |

首个实现阶段仅交付账户、知识库、入库任务、检索及聊天接口；练习和报告按规划阶段加入。这里列出完整契约，避免后续模块各自定义不兼容字段。
